# Как перевести DeepSeek Harness на свой язык

Это руководство — наш опыт перевода веб-клиента DSH на русский: 594 секции и 69 177 строк,
которые сейчас работают у нескольких тысяч человек. Здесь нет теории локализации; здесь
описано, как устроен словарь харнесса, что ломается на каждом шаге и как это проверить
машиной, а не глазами.

## Как устроены строки в DSH

Веб-клиент не держит текста в компонентах. Каждый пакет объявляет секцию и словарь:

```ts
locale.register('settings.models', {
  en: { reorderModel: 'Reorder model', fetchKeepOne: 'Keep at least one model checked.' },
  zh: { reorderModel: '重新排序模型', fetchKeepOne: '至少保留一个选中的模型。' },
})
```

Секция — это пространство имён; ключ уникален внутри неё, но не между секциями: `cancel`
есть в десятках словарей, и это разные строки. Рантайм `@deepseek-ai/dsh-client-locale`
подменяет словарь на клиенте, поэтому сторонний перевод не требует правок в харнессе.

Найти все секции:

```bash
grep -rE "register\(\s*['\"]|PropsLocale<\s*['\"]|export const NS = ['\"]" packages --include=*.ts --include=*.tsx
```

## Шаг 1. Соберите английские строки

Не переводите из интерфейса: словарь придётся поддерживать, а не пересматривать. Выгрузите
`en` каждой секции в JSON — это ваш вход и ваш эталон:

```js
const start = /(?:export\s+)?const\s+en\b[^=]*=\s*\{/.exec(text)          // где словарь
// дальше — сбалансированные скобки от первого `{`, чтобы не зацепить `zh`
```

Две ловушки, на которых мы потеряли часы:

- **Словарь не всегда в том же файле.** `register` живёт в `mount.ts`, а `en` — в
  соседнем `locales.ts`. Если в файле регистрации словаря нет, смотрите каталог.
- **Имя секции не всегда литерал.** Бывает `export const NS = 'cuaPermissions'` плюс
  `register(NS, …)`. Ищите тройку: `register('x')`, `PropsLocale<'x'>`, `NS = 'x'`.

## Шаг 2. Переводите ключ за ключом, не строку за строкой

Правила, которые у нас выросли в проверки:

- **Плейсхолдеры неприкосновенны.** `{count}`, `{name}`, `{version}` обязаны остаться
  в переводе, иначе строка отрисуется с пустотой. Проверяется регуляркой по обеим сторонам.
- **Формы числа.** Там, где английский держит `one`/`other`, русский держит три формы.
  Мы генерируем пары из одного шаблона и требуем, чтобы форма `one` и `other`
  существовали вместе с базовым ключом.
- **Технические имена не переводятся:** имена продуктов (`DSH`, `LiveShare`), названия
  шрифтов (`Comic Sans MS`), обозначения клавиш (`Ctrl+S`), команды (`dsh plugin remove …`).
  Держите их в отдельном списке разрешений, иначе очередная проверка их «исправит».
- **Один термин — один перевод.** У нас `session` — всегда «сессия», `turn` — «раунд»,
  `step` — «шаг». Без глоссария через сто строк появляется «сеанс», и это видно в интерфейсе.

## Шаг 3. Проверяйте машиной

Всё, что можно проверить, должно падать на сборке. Наши проверки, которые реально ловили
дефекты:

| проверка | что ловит |
|---|---|
| ключи, которых нет в шаблоне | опечатка в ключе: строка молча не появляется |
| ключи, добавленные харнессом | новый ключ без перевода после обновления |
| пары форм числа | пропущенная форма, и вместо числа — пусто |
| плейсхолдеры | `{count}` потерян или переименован |
| остатки латиницы и иероглифов | непереведённая строка |
| запрещённые термины | «сеанс» рядом с «сессия» |
| длина относительно шаблона | перевод втрое длиннее и рвёт вёрстку |

**Главная ловушка проверок:** не собирайте шаблоны «по ключу из любого файла». Ключ
`cancel` есть в сотнях словарей, и если сложить их в одну кучу, любая русская строка
совпадёт с русской строкой из чужой локализации. У нас из-за этого проверка выдавала
2 368 ложных находок, за которыми не было видно трёх настоящих. Сравнивайте в пределах
секции — или отсекайте шаблоны с кириллицей, если секции нет.

## Шаг 4. Держите синхронизацию с харнессом

Харнесс двигается быстро: за неделю вышло три тега, и один из них (0.2.2-alpha.2) добавил
745 строк в девяти новых секциях. Плановый прогон проверок против свежего дерева — это не
роскошь, а способ не отстать на релиз:

```bash
git -C ../deepseek-harness fetch --tags
git -C ../deepseek-harness checkout dsh-v0.2.2-alpha.2
npm run verify -- ../deepseek-harness/packages
```

Отдельно проверяйте **совместимость рантайма**: у 0.2.2-alpha.2 сменилась зависимость
(`cordis@~4.0.6-alpha.1`), и наш диапазон её не пускал — установка падала с `ERESOLVE`,
пока мы не расширили `peerDependencies`.

## Шаг 5. Не доверяйте именам секций

Секции приходят из кода, и в них попадает мусор. У нас жили две «секции» с именами файлов
(`.runs.json`, `.ndjson.zst`) — 72 строки, которых никто никогда не видел, и они искажали
и счёт, и проверки. Если имя секции похоже на имя файла или оканчивается точкой — почти
наверняка это ошибка разбора, а не словарь.

## Шаг 6. Выпускайте так, чтобы это можно было повторить

- Собранный код держите в репозитории и сверяйте пересборкой с коммитом: иначе
  пользователь получит устаревший бандл, а проверки этого не увидят.
- Публикацию отдайте CI по тегу: у нас ручная публикация дважды застревала на 2FA,
  и версии просто не доезжали до реестра.
- Числа в README (секции, строки, размер) считайте из пакета, а не вручную: за релиз
  они разъезжаются дважды.

## Что почитать у нас

- `scripts/audit.mjs` — все проверки в одном месте, включая отсечку шаблонов с кириллицей.
- `scripts/keep-english.json` — список того, что остаётся латиницей, с причиной для каждой записи.
- `scripts/terminology.json` — глоссарий и запрещённые варианты.
- `docs/harness-descriptors-ru.patch` — как переводятся описания плагинов в каталоге.
