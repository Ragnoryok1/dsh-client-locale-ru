# Почему имена плагинов не переводит языковой пакет

Этот документ фиксирует измерение, на котором основана ветка
`locale/ru-plugin-descriptors` в дереве харнесса, и способ её воспроизвести.

## Механизм

Название и описание плагина на странице «Плагины» приходят не из словарей. Загрузчик
читает `locale/<язык>.json` внутри самого пакета и собирает из них карту перевода
(`packages/boot/app-boot/src/package-meta.ts`, функция `dictionariesOf`), а сервис локали
разбирает эту карту без обращения к словарям:

```ts
/**
 * Resolve package text through the active language's declared fallback chain.
 * Plain strings stay verbatim; maps do not consult registered dictionaries.
 */
resolveText(text: LocalizedText): string { … }
```

Отсюда следствие: языковой пакет переводит **строки** плагина, но не его **имя**. Имя
становится русским только файлом `locale/ru.json` в самом пакете.

## Измерение

```
node scripts/descriptor-coverage.mjs ../deepseek-harness/packages
```

| показатель | значение |
|---|---|
| пакетов с `locale/en.json` | 221 |
| строк `meta.title` / `meta.description` | 221 / 35 |
| пакетов с `locale/zh.json` | 219 |
| пакетов с `locale/ru.json` до правки | **0** |
| названий, читаемых как ярлык (не идентификатор) | 34 |

То есть у проекта есть китайские дескрипторы почти везде и русских нет ни одного. Для
русского пользователя это значит, что имена плагинов остаются английскими при любом
языковом пакете — в том числе при пакете конкурента.

## Правка

`descriptor-ru.json` в этом репозитории содержит 32 перевода (два `@local/*` пакета из
дерева — демонстрационные, они не публикуются). `scripts/apply-descriptor-ru.mjs`
раскладывает их по `locale/ru.json` указанного дерева:

```
node scripts/apply-descriptor-ru.mjs ../deepseek-harness/packages --write
```

Пишутся только те поля, которые объявлены в `en.json` пакета: лишний ключ — это не перевод,
а расхождение формы, и валидатор загрузчика на нём откажет.

## Проверки

- **Форма:** у всех 32 файлов набор ключей совпадает с `en.json` — 0 расхождений.
- **Живой экземпляр:** второй `dsh web` из исходников на другом порту показал «Команды
  агентов», «Голосовой ввод», «Автоматическая проверка разрешений», «Инструменты
  разработчика» вместо английских названий, с русскими описаниями.
- **Дрейф:** `npm run check:descriptors -- <дерево>` сравнивает текущий английский текст со
  снимком, с которого переводили. Проверено инъекцией: подмена снимка даёт отказ.

## Что делать при обновлении харнесса

1. `npm run report:descriptors -- <дерево>` — посмотреть, появились ли новые читаемые названия.
2. Добавить переводы в `descriptor-ru.json`.
3. `node scripts/record-descriptor-sources.mjs <дерево>` — записать новый английский снимок.
4. `npm run check:descriptors -- <дерево>` — убедиться, что расхождений нет.
5. `node scripts/apply-descriptor-ru.mjs <дерево> --write` — разложить файлы.
